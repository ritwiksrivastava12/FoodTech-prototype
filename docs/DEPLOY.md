# Deploying FoodMate (Render, free tier)

The repo is deployment-ready: `render.yaml` defines Postgres + API + static frontend.
The frontend uses `HashRouter`, so static hosting needs no rewrite rules.

## Steps

1. **Push to GitHub**
   ```bash
   cd D:\FoodTech
   git init
   git add -A
   git commit -m "FoodMate prototype"
   # create an empty repo on github.com, then:
   git remote add origin https://github.com/<you>/foodmate.git
   git push -u origin main
   ```
   Do **not** commit real secrets — `.env` files should stay local
   (only `.env.example` files are in the repo).

2. **Render → New → Blueprint**, select your repo. Render will create:
   - `foodmate-db` (free Postgres)
   - `foodmate-api` (FastAPI, seeded automatically on first boot)
   - `foodmate-web` (static React build)

3. **Fix the two URLs if names collided.** If Render renamed a service
   (e.g. `foodmate-api-abc1`), update:
   - backend `CORS_ORIGINS` → your actual frontend URL
   - frontend `VITE_API_BASE` → your actual backend URL
   Then Manual Deploy both.

4. **Verify**: open `https://<your-api>.onrender.com/api/health`,
   then the frontend URL → log in with `demo@foodmate.app / demo1234`.

## Notes / limits

- Free services **sleep after inactivity** — first load takes ~30–60s. Normal.
- Render's free Postgres is time-limited; if it expires, create a free DB at
  **Neon** or **Supabase** and paste its connection string into the backend's
  `DATABASE_URL` env var. No code change needed.
- To use a real LLM in production, set `AI_PROVIDER=openai` (or anthropic/gemini)
  plus the matching `*_API_KEY` on the backend only. Never in frontend env.
- `JWT_SECRET` is auto-generated by the blueprint. Changing it logs everyone out.
